## 訪問看護シフト＋訪問ルート最適化SaaS（B1）

作成日: 2026-05-18

## エグゼクティブサマリー（結論ファースト）

**評定: 51 / 100点。Go判断は推奨しない（条件付きで部分的にGo）。**

調査の結果、本アイデア「訪問看護シフト＋訪問ルート最適化SaaS」は **「課題は本物・市場は確実に伸びる・ただし既にレッドオーシャン化しつつあり、エニケアが勝てる経路が極めて狭い」** と結論する。

主要な発見:
1. **ホワイトスペースは無い**。「訪看×シフト×ルート最適化×AI」は既に **ZEST（業界No.1・1秒で自動生成・モバカルとAPI連携）／CareMaker（直近1億円調達・シフト自動化済）／カナミックかんたんAI訪問ルート（2024-07リリース・カナミック5万事業所基盤）／iBow + AI訪問計画（シェア17.5%・3,028ステーション・eWeLL社内提供）** という4強が既に占拠している。「自社クライアントのPoC可能」という強みは事実だが、3社のPoCで月10万 ×3 = **月30万のARR** に過ぎず、エニケアの本業（採用代行）の収益規模に比べて意義が薄い。
2. **エニケアのコアアセット（候補者DB・看護師人材ネットワーク・採用代行ノウハウ）と本アイデアの相性が悪い**。SaaSプロダクトの開発・保守・カスタマーサクセス・エンタープライズセールスはエニケアの現在の組織能力からの距離が遠い。AIエンジニア1名のみで競合（ZESTは7.6億円調達済、CareMakerは累計1.5億円超調達）と戦うのは無理。
3. **粗利30%は技術的にクリア可能だが、その前にCAC（顧客獲得コスト）でPL破綻するリスクが高い**。バーティカルSaaSのCACペイバック期間は18-24ヶ月が標準で、月10万 × 24ヶ月 = LTV 240万を回収するために、看護師ヒアリング・デモ・契約まで1社あたり3-6ヶ月の営業工数が必要。エニケアにB2Bエンタープライズセールス人材がいないため、ここが致命的ボトルネック。

**部分的Goの形**: ピボット案として「**シフト＋ルート最適化SaaS単体**」ではなく、「**訪看ステーション向け『採用×シフト×ルート』統合プラットフォーム**」として、エニケアの強み（採用）を残しつつシフト/ルートは **ZEST/CareMakerと再販パートナーシップ** を結ぶ形を推奨する。詳細は「結論」セクションへ。

### 2.5 ホワイトスペース判定

**結論: ホワイトスペースは無い**

- 「シフト×ルート×AI×訪看」: ZEST・CareMaker・カナミックの3社が既に占拠
- 「電子カルテ＋シフト＋勤怠」: iBow が独走、カイポケが追随
- 「電子カルテと API連携するルート特化SaaS」: ZESTがモバカルとの連携で先行
- 「電子カルテにルート最適化を組み込み」: iBow が AI訪問計画・AIルート提案で先行

エニケアが入る余地があるとすれば、以下のニッチに限られる:
1. **超小規模ステーション（看護師2.5-5人）向け** の極めて安価（月1-2万円）なシンプル版（→単価が低くPL成立しない）
2. **特定の連携先（拡張機能）** として既存SaaSのアドオンになる（→主導権を握れない）
3. **採用機能と統合した独自ポジション**（→これはピボット案として後述）

## 3. 他業界の類似サービス成功事例（★最重要）

### 3.1 シフト＋ルート最適化SaaSの成功事例

### 3.2 「なぜ他業界の成功事例が訪看に流れ込まないのか」

3.1の整理から、以下の壁が見える:

1. **医療資格マッチングの複雑さ**: 看護師、准看護師、PT、OT、ST、管理者要件など、訪問内容ごとに有資格者要件が異なる。配送業の「ドライバー全員に同じ荷物を運ばせられる」と全く違う。
2. **加算要件の制約**: 24時間対応体制加算、特別管理加算、緊急時訪問看護加算、ターミナルケア加算など、シフト・記録・人員配置が報酬に直結する。シフト最適化が「報酬最大化」と「労務削減」の二項対立になる。
3. **利用者の希望時間帯・相性**: 「この看護師でないと嫌」「午前中の特定の時間に来てほしい」等、配送の「不在票でリトライ」が許されない。
4. **地理的制約 + 移動時間**: 移動時間は労働時間に含まれる/含まれないの解釈論争もあり、ルート設計が直接労務費に影響。
5. **オンコール体制**: 夜間・休日のオンコール当番のバランス、属人化しやすい。
6. **電子カルテとの密結合**: シフト＝記録＝レセプトのデータが連動。電子カルテと別物のシフトSaaSは「もう一つの入力先」として嫌われる。

→ **これらの壁を超えて参入したのが ZEST・CareMaker・カナミック・iBow であり、彼らが先行者利益を握っている。**

| iBow KINTAI（勤怠） | 公開料金不明、iBow ユーザーへアップセル | per ステーション |
| カイポケ訪問看護 | **25,000円**（40機能込み・定額） | per ステーション |
| ZEST | 非公開（推定3-10万円/月） | per ステーション + 利用看護師数 |
| CareMaker | 非公開（初月無料） | per ステーション |
| ケアコラボ | 10名 8,800円～50名 44,000円 | per ユーザー段階制 |
| Loogia（配送） | 拠点数・車両台数月額（推定3-15万円） | per 拠点 |
| ジョブカン勤怠 | 200円/人 | per ユーザー |
| Airシフト | 個別 | per ユーザー |

### 4.2 想定モデルの妥当性検証

提案: **月3-10万円 × 100社 = 月300-1,000万円ARR**

- 月3万円: カイポケ電子カルテ（25,000円）と競合になる価格帯。電子カルテとセットで提供するならアリだが、シフト＋ルート単体だと「もう一つの月額」として敬遠される
- 月10万円: ZEST のフル機能と同等ライン。エニケアブランドではこの価格で勝負しづらい

**現実的価格レンジ**: 月3-5万円（電子カルテ既存ユーザーへのアドオン）または月8-10万円（フルパッケージ・電子カルテ非利用ステーション向け）

### 4.3 粗利率の算定

| 項目 | 金額（月10万円ARR × 100社の場合） |
|------|------|
| 売上 | 1,000万円/月（年1.2億円） |
| **直接原価** | |
| - クラウドインフラ（GCP/AWS） | 50万円/月 |
| - 地図API（Google Maps Platform）| 30万円/月（最適化呼び出し量による） |
| - 第三者API（電子カルテ連携手数料） | 30万円/月 |
| - AIモデル推論（OpenAI/Gemini）| 20万円/月 |
| - データバックアップ・セキュリティ | 20万円/月 |
| **直接原価小計** | **150万円/月（売上の15%）** |
| **粗利** | **850万円/月（粗利率85%）** |

→ **純粋なSaaSとしての粗利率は85%程度を狙える**。粗利30%足切りは余裕でクリア。

**ただし**: 「カスタマーサクセス・導入支援・営業」を**広義の原価**に含めると以下のように悪化する:

| 項目 | 金額（同条件・スタートアップ初期） |
|------|------|
| 売上 | 1,000万円/月 |
| インフラ系直接原価 | 150万円/月 |
| カスタマーサクセス（1名・100社サポート） | 60万円/月（人件費＋諸経費） |
| 導入支援（1名・新規10社/月対応） | 70万円/月 |
| **広義の原価合計** | **280万円/月** |
| **広義粗利** | **720万円/月（72%）** |

→ それでも70%超を維持できる。

**最大の問題はCAC（顧客獲得コスト）**: SaaS業界のベンチマークでCACペイバック期間は **12-24ヶ月** が健全。月10万 × 24ヶ月 = LTV 240万を1社に対して、営業＋マーケに120万円程度しか使えない。エンタープライズセールス1名の年収を500万円とすると、1名で年4-5社しか取れない計算。

### 4.4 SaaS業界の粗利率ベンチマーク

- 一般的なSaaS: **75-80%が健全、トップティアは80%超** [Stripe SaaS粗利益率](https://stripe.com/resources/more/saas-gross-margin-explained-what-it-is-and-why-it-is-important)
- eWeLL（iBow）: 営業利益率 **約34%**（売上25億・営業利益8.6億の試算）[ログミーファイナンス](https://finance.logmi.jp/articles/383560)

→ **粗利30%足切りは技術的に余裕でクリア**。問題は粗利ではなく、CACと開発投資の回収。

### 5.2 参入障壁の構造

| 障壁 | エニケアにとっての難易度 |
|------|------|

| **24時間サポート体制** | 高。訪看は24時間稼働、システム停止＝事業停止 |
| **3省2ガイドライン準拠のセキュリティ** | 高。AWS/GCP+自社運用で対応可能だが追加コスト |

### 5.3 「既存電子カルテとの連携必要性」が最大の難所

**ファクト**: 訪看ステーションが現実に欲しいのは「**シフト・ルート・記録・請求が全部つながった一体型システム**」。iBow + iBow KINTAI、カイポケ（40機能込み月25,000円）、ZEST + モバカル等は **既にこの一体感を提供**。

エニケアが「シフト＋ルート単体のSaaS」を出しても、ユーザー側は「電子カルテと連携してないから二重入力になる」と拒否する。

連携するなら、iBow（eWeLL）、カナミック、カイポケ（SMS）の3社と個別にAPI接続を交渉する必要があるが、これらは **競合関係** にあるため非協力的になる可能性が高い。ZESTがモバカル（マイナーな電カル）としか連携できていないのも、メインプレイヤーが連携を渋っている証左。

| 項目 | 配点 | 採点 | 根拠 |

**最大の弱点（率直に）**: **B2Bエンタープライズセールスのケイパビリティが致命的に欠けている。**

訪看ステーションのSaaS導入は典型的なエンタープライズ営業（管理者ヒアリング→デモ→無料トライアル→稟議→契約）で、1社獲得まで3-6ヶ月かかる。エニケアの現在の組織には、医療系SaaSを売れる営業マネージャー・SDR（インサイドセールス）・FS（フィールドセールス）・CS（カスタマーサクセス）の体制がない。

これを構築するために必要な投資:
- 営業マネージャー1名（年収800万円）
- FS 2名（年収600万円 × 2 = 1,200万円）
- SDR 1名（年収400万円）
- CS 1名（年収500万円）
- **年間人件費だけで約3,000万円**（諸経費込みで4,000-5,000万円）

→ 月10万円 × 100社 = 年1.2億円のARRに対して、営業・CS人件費だけで4,000-5,000万円かかる。残り7,000万円から開発費・インフラ費・地代家賃を引くと、黒字化は **3年目以降**。

エニケアの本業（RPO）の年商と比較して、新規事業として手を出すリターンが見合うかは要検討。

## 9. リスクと対応策（主要5個）

### リスク① 法人セールス力不足
**内容**: エニケアにB2Bエンタープライズセールス人材がいない。SaaS営業の経験者ゼロ。
**影響度**: 致命的。これが解決しないと事業立ち上げ自体が不可能。
**対応策**:
- 採用代行業務の延長で「既存顧客8社からのアップセル」に絞り、新規開拓は当面しない
- もしくは医療系SaaS営業経験者を1名スカウト（年収800-1,000万円コミット必要）
- 上記が無理なら **本案は撤退判断**

### リスク② 既存電子カルテSaaSとの競合
**内容**: iBow・カナミック・カイポケが既にシフト・ルート機能を内包または追加中。エニケアの単独SaaSは「もう一つの入力先」として嫌われる。
**影響度**: 高
**対応策**:
- 電子カルテとの API連携を最初から仕様に組み込む（ただし iBow 等が API公開していない場合は不可能）
- 「電子カルテに不満を持つステーション」をターゲットに限定（市場が小さい）
- 連携できない場合は **本案は撤退判断**

### リスク③ 意思決定サイクルの長さ
**内容**: 訪看ステーションのSaaS導入は管理者ヒアリング→デモ→無料トライアル→稟議→契約で **3-6ヶ月**、その間の営業工数が高い。
**影響度**: 高（CAC回収を阻害）
**対応策**:
- 既存クライアント（ARK・LCC・いちご）の信頼関係を活用してデモ→契約を短縮
- IT導入補助金の申請サポートをセット販売（補助金で導入コスト1/2、購買障壁を下げる）
- 初月無料・3ヶ月トライアルで体験ハードル下げる

### リスク④ 開発リソース不足
**内容**: AIエンジニア1名で ZEST（複数エンジニア）・CareMaker（複数エンジニア）・eWeLL（上場企業の開発部隊）と戦うのは不可能。
**影響度**: 致命的
**対応策**:
- 自社開発を諦め、ZEST/CareMakerと **再販パートナーシップ** を結ぶ（後述のピボット案）
- もしくは1.5-2億円の追加開発投資を確保し、エンジニア3-5名を採用

### リスク⑤ 介護報酬改定リスク
**内容**: 2-3年に1度の介護報酬改定（次回2027年4月）で機能改修必須、対応遅延でユーザー離れ。
**影響度**: 中
**対応策**:
- 改定情報を継続ウォッチ、改定6ヶ月前から仕様変更着手
- 改定対応費用を年商の5-10%として予算化

## 10. 結論

### 戦略的に「やる」価値があるか

**結論: 単体SaaSとしてはNo。条件付きピボットならYes。**

#### 単体SaaSとして見送る理由（3つ）

1. **ホワイトスペースが無い**。ZEST/CareMaker/カナミック/iBowの4強が既に占拠し、特に ZEST は累計9.6億円調達済み・業界No.1の地位を固めつつある。後発でひっくり返すには、決定的な技術差別化または営業力差別化が必要だが、エニケアにはどちらもない。

2. **エニケアの組織能力ギャップが大きすぎる**。AIエンジニア1名・エンタープライズセールス経験者0名で、上場企業（eWeLL）や資金調達済みスタートアップ（ZEST・CareMaker）と戦うのは無理。最低でも開発3名・営業3名・CS 2名の追加採用が必要で、年5,000-7,000万円の固定費が発生。

3. **本業（採用代行）との親和性が低い**。看護師人材ネットワーク・候補者DBという最大のアセットがSaaS事業に活きない。共通点は「顧客が訪看ステーション」だけ。

| **損益** | **△2,600万円** | **△1,980万円** | **△700万円** |

→ 3年目でも赤字。4-5年目で黒字化、累計赤字回収まで6-7年。

**シナリオB: 採用×シフト統合プラットフォーム（ピボット案）**

| 項目 | 1年後 | 2年後 | 3年後 |
|------|------|------|------|
| 契約社数 | 8（既存）→ 20社 | 50社 | 80社 |

| ARR | 4,800万円 | 1.5億円 | 2.88億円 |
| 営業・CS人件費（採用代行と兼務） | +500万円（兼務） | +1,500万円 | +2,500万円 |
| 開発・インフラ（再販でほぼゼロ） | +200万円 | +300万円 | +500万円 |
| **損益（増分）** | **+4,100万円** | **+1.32億円** | **+2.58億円** |

→ 採用代行の既存収益+αとして十分意味がある。

### 他案と比べた優位性・劣位性

| 観点 | 優位性 | 劣位性 |
|------|------|------|
| **市場性** | ◎ 訪看市場は2040年まで確実に伸びる | △ 競合4強が既にいる |
| **エニケアの強み活用** | △ 既存顧客でPoC可能 | × 候補者DB・看護師ネットワークが活きない |
| **収益性** | △ 粗利率は高い | × CAC回収まで時間がかかる |
| **実現可能性** | △ 既存顧客の協力得られる | × エンタープライズセールス・SaaS開発のケイパビリティ欠如 |
| **3年後の規模感** | × 5,000万円ARR（本業比小さい） | × 本業の成長と比較してリターンが見合わない |

→ 本コンテストの他アイデア（①〜④、⑥〜）と比較すると、市場性は高いが「エニケア親和性」と「実現可能性」で大きく劣る。

### もしGoなら最初の100日にやるべきこと3つ

**前提**: 単体SaaSではなく **「採用×シフト統合プラットフォーム」ピボット案** で進める場合。

1. **ZEST・CareMaker・iBow と再販/OEM提携の交渉（Day 1-30）**
   - 3社それぞれに「エニケアの既存顧客にシフト＋ルート最適化を再販する」提案
   - 再販マージン15-25%目安、エニケアは「採用代行」を主役にSaaSを抱合せ販売
   - 1社でも合意できれば事業化可能、3社全滅なら撤退

2. **既存クライアント8社（ARK・LCC・いちご・他）にPoCヒアリング（Day 31-60）**
   - 「採用＋シフト＋ルート」セットで月20-30万円の販売モデルへの反応を聞く
   - 特に、シフト管理に困っている管理者の生の声を録音・分析
   - PoC参加意向2-3社獲得を目標

3. **「採用×シフト統合ダッシュボード」の最小プロトタイプ開発（Day 61-100）**
   - AIエンジニア1名で、エニケアの採用代行データ + ZEST/CareMakerのシフトデータをひとつの管理画面に統合
   - 月次レポート機能（「採用予定 vs 実シフト充足率」「ルート最適化による稼働率改善」）
   - PoC参加2社で実際に運用、月次でフィードバック収集

100日後の判断基準: **PoC 2社が「月20-30万円の追加課金OK」と言うか**。Yesなら正式事業化、Noなら撤退。

### 最終提言

**「⑤訪問看護シフト＋訪問ルート最適化SaaS」は、原案のまま単体SaaSとして進めるべきではない。**

ただし、戦略的に **「採用×シフト×ルート統合プラットフォーム」へピボット** すれば、エニケアの本業（採用代行）の延長線上で月20-30万円/社のアップセル機会となり、3年で年商1.5-3億円規模の事業に育つ可能性がある。

このピボット案は、本コンテストの審査基準のうち:
- ④ エニケア親和性: 5点 → **12点**（本業のアップセル）
- ② 実現可能性: 10点 → **20点**（SaaS開発不要、再販モデル）
- ① 財務: 18点 → **24点**（CAC低、PoCから黒字化早い）
- 合計: **57点 → 80点**

を達成し得る。

審査委員会には **「原案（単体SaaS）はNo、ピボット案（採用×シフト統合）はYes」** という二段構えで提案することを推奨する。
