# バッチスカウト文生成スキル pro 版

`csv-scout` の入出力フロー + `generate-scout-pro` の生成原則を合成したバッチ生成スキル。
全候補者に対して 4ブロック構成（opening / bridge / facility_intro / closing_cta）・属性別修飾句・トーン別動詞・給与調整・3階層フィルタを適用する。

## 引数

- 第1引数: 会社名（省略可）例: `sato-hospital`
  - 省略時: `companies/` 配下のディレクトリ一覧を確認し、1社のみなら自動選択、複数あればユーザーに選択を促す
- 第2引数: CSVファイルパス（省略可）
  - 省略時: `~/Downloads/` 内の `profiles_*.csv` で最新のファイルを自動検出
- オプション:
  - `resend` → 再送モード
  - `seishain` → 正社員テンプレート強制

例:
```
/csv-scout-pro
/csv-scout-pro resend
/csv-scout-pro sato-hospital /Users/aki/Downloads/profiles.csv
/csv-scout-pro sato-hospital /Users/aki/Downloads/profiles.csv resend
```

## 実行手順

### 1. 引数パース・確認

引数 `$ARGUMENTS` から会社名・CSVパス・オプションを取得。

**初回/再送の確認（必須）**:
引数に `resend` が含まれていない場合、**生成を開始する前に必ずユーザーに確認する**:
「初回送信ですか？再送ですか？」
- 「初回」→ 初回テンプレート
- 「再送」→ 再送テンプレート

**会社名の自動判定**:
1. 引数に会社名が含まれていない場合（引数がCSVパスで始まる場合）、`companies/` 配下のディレクトリを `ls` で一覧取得
2. 1社のみ → その会社を自動選択
3. 複数社 → ユーザーに選択を促す
4. 0社 → エラー

**CSVパスの自動判定**:
引数がファイルパス（`/` で始まる or `.csv` を含む）なら会社名ではなくCSVパスと判定。

**CSVパス省略時の自動検出**:
引数にCSVパスが含まれない場合:
1. `ls -t ~/Downloads/profiles_*.csv | head -1` で最新のプロフィールCSVを検出
2. 見つかったら「`[ファイル名]` を使用します」と表示して続行
3. 見つからなければエラー

### 2. ファイル読み込み

**読み込むファイル（会社別に閉じる — 他社のファイルは一切読み込まない）:**
```
- companies/[会社名]/profile.md          → 会社情報・想定年収レンジ・トーン傾向
- companies/[会社名]/templates.md        → テンプレート本体 + フィルタリング条件
- companies/[会社名]/recipes.md          → 共通ルール・接点対応表・NGパターン（あれば参照、型はめマトリクスは pro では使わない）
- companies/[会社名]/history/examples.md → 良い例集（あれば参考）
- workspace/phase0-full-refined.md       → 4サンプル参照（pro 原則の温度感を確認するため。判断に迷ったら参照）
```

**読み込まないファイル:**
- `knowledge/learnings.md` — エッセンスは recipes.md に反映済み
- 他社の `companies/` 配下のファイル一切

### 3. CSV読み込み・フィルタリング

入力CSVの必須列: `member_id`
その他の列（`qualifications`, `experience_type`, `experience_years`, `desired_employment_type`, `self_pr`, `special_conditions`, `work_history_summary`, `age`, `employment_status`, `desired_area` 等）を使用。

**フィルタリング（必須）**: 以下の順で除外する。除外した候補者は完了報告で一覧表示する（member_id + 除外理由）。

1. **スカウト送信済みの除外**: `scout_sent_date` 列に値がある候補者は自動除外する（除外理由: 「スカウト送信済み（{日付}）」）
2. **会社別フィルタリング（除外条件）**: templates.md の「スカウト対象フィルタリング」セクションの **除外条件** に該当する候補者を除外（除外理由: 「除外条件: [具体]」）
3. **対象（要警告）/ 対象不明** はここでは除外せず、生成時に警告を付ける

### 4. テンプレート判定（候補者ごと）

1. 引数に `seishain` → 正社員テンプレート
2. 引数に `resend` → 再送テンプレート（正社員/パートは下記で判定）
3. `desired_employment_type` に「正職員」を含む → **正社員テンプレート**（「パート・バイト」も同時に含まれていても正社員を優先）
4. 「パート・バイト」のみ（正職員を一切含まない）→ パートテンプレート

`template_type` の値:
- `パート_初回` / `パート_再送` / `正社員_初回` / `正社員_再送`

### 5. パーソナライズ文の生成（候補者ごとに pro パイプライン）

**csv-scout の型はめマトリクスは使わない。** 全候補者を pro 原則で生成する。
情報量 sparse の候補者でも、構文を切り替えて 4ブロック構造で書く（5-2 の `young_sparse` 等を参照）。

#### ステップ5-1: 候補者属性判定（3軸＋対象判定＋給与判定）

**A. 情報量判定**

| 区分 | 条件 |
|---|---|
| **rich** | self_pr 100字以上 OR 職務経歴詳細あり |
| **moderate** | experience_type＋希望条件あり |
| **sparse** | 基本情報のみ／PR 50字未満／職歴半年未満 |

**B. 経験タイプ判定**

| 区分 | 条件 | 例 |
|---|---|---|
| **veteran_with_specialty** | 経験10年以上＋専門資格（感染管理認定／DMAT／管理職経験 等） | 48歳師長×感染管理認定 |
| **pr_values_explicit** | PR に「傾聴」「協調性」「○○を大切に」「寄り添う」等の**姿勢が明記** | 47歳PT×傾聴 |
| **young_sparse** | 経験1年未満 ＋ PR 50字未満 | 21歳看護1年未満×PR12字 |
| **blank_career** | 離職中 or ブランク3ヶ月以上 ＋ 多職歴 | 48歳離職9ヶ月×大学病院～有料老人ホーム |
| **general** | 上記いずれにも該当せず | デフォルト |

**C. トーン判定**

| トーン | 該当条件 | 文体特徴 |
|---|---|---|
| **business** | 病院系・40代以上ベテラン・専門資格保有 | 敬語ベース・事実重視・「存じます」系 |
| **casual** | 訪看リハ・複合体制・若手・カジュアル雰囲気の会社 | 「！」OK・「カルチャー／マッチ」等カタカナ語OK |
| **letter** | 離職中・40代後半以上・多職歴・letter PR | お手紙調・「お迎えしたい」「ご縁」「幸い」等 |

会社のトーン傾向は `companies/[会社名]/profile.md` か `templates.md` の文体から推定可能。
候補者属性によって同じ会社でもトーンを切り替える（離職中・ブランク → letter）。

**D. 対象フィルタ判定（templates.md のフィルタ階層）**

`companies/[会社名]/templates.md` の「## スカウト対象フィルタリング」セクションを読み、候補者を以下の3階層に分類:

| 区分 | 対応 |
|---|---|
| **対象（明確）** | 通常通り生成。警告なし |
| **対象（要警告）** | 生成するが、属性判定の「警告」フィールドに警告文を出力 |
| **対象不明** | どの階層にも該当しない場合。警告つきで生成（オペレーター判断に委ねる） |

※ 除外条件はステップ3-2 で既に弾いている。ここでは要警告・対象不明のみ判定。

**警告文の作り方**:
- なぜ要警告に分類したか（経験領域の違い等）
- どう接続したか（理念フィット・転用可能なスキル等）
- 例: 「障害福祉のみの経験。主対象（高齢者介護）からは外れますが、管理者経験/理念フィットでパーソナライズ可能と判断しました」

**E. 給与調整判定（全社共通で必ず実行）**

候補者の希望年収とテンプレートヘッダー年収の関係を見て、ヘッダー削除／文面訴求の有無を決める。

**抽出元**: 候補者プロフィールの `special_conditions`（こだわり条件・特記事項）

**抽出ルール**:
- 「年収500万円以上可能」「年収600万円以上可能」「年収700万円以上可能」等を含む → **500万以上希望**
- 「年収400万円以上可能」を含む（500万以上は含まない） → **400万以上希望**
- どちらも含まない／空欄／「-」「未入力」「なし」 → **希望なし**

**モード A: profile.md に「給与訴求マトリクス」セクションあり**

会社が明示的にマトリクスを定義している場合はそれに従う:
- **A: 即マッチ** → ヘッダーをパターンAに差し替え + 連絡理由フックAを bridge or facility_intro に1〜2文で挿入
- **B: 昇給で到達** → ヘッダーをパターンBに差し替え + 連絡理由フックBを挿入
- **C: 訴求しない** → デフォルトヘッダー（既存）使用、給与訴求フックは入れない

**モード B: マトリクスなし（フォールバック）**

profile.md に「給与訴求マトリクス」がない場合は、profile.md の「想定年収」レンジ（入職1年目／5年目／10年目額）を読み、以下のマトリクスで判定する。

| 候補者希望 vs 想定年収レンジ | ヘッダー処理 | 文面処理 |
|---|---|---|
| 候補者希望 > 想定年収max（大幅下回り） | テンプレートヘッダーから「想定年収XXX万円〜」を削除 | 触れない |
| 想定年収max ≥ 候補者希望 ＞ 想定年収1年目（届く可能性） | 同上削除 | 「当院のキャリアモデル（10年目XXX万円）の中で到達可能な範囲としてご相談いただけます」を1文挿入 |
| 想定年収1年目 ≥ 候補者希望（即マッチ） | そのまま | 「ご希望の年収帯にもお応えできる可能性がございます」を1文挿入 |
| 希望なし | そのまま | 触れない |

**ヘッダー削除の方法**:
- ヘッダー全体を残しつつ「想定年収XXX万円〜！」だけを除去
- 年間休日・残業・時短・駅近等の他訴求は残す

**訴求時のヘッジ表現（モードA／B 共通・必須）**:
- ❌ 「〜になります」「確実に到達」（断定）
- ✅ 「〜のモデルケース」「お応えできる可能性」「実現可能な範囲」「ご相談いただけます」
- 候補者の希望額は「500万以上」のレンジ表記で引用、具体額の差分計算は避ける
- 想定年収の具体数字（10年目460万円等）は1回だけ・括弧書きで添える程度

#### ステップ5-2: 属性別 opening 修飾句マッピング

| 経験タイプ | opening 修飾句 | 結び動詞 |
|---|---|---|
| **veteran_with_specialty** | 〜ご経験と〜ご視点を拝見しました | お迎えしたい方だと感じ |
| **pr_values_explicit** | 〜を大切にされている方／〜を軸にされているご姿勢 | 来ていただきたいと思い／お迎えしたいと感じ |
| **young_sparse** | 構文外し「〜と拝見しました」→「ご検討いただけたら」 | ご検討いただけたらと思い |
| **blank_career** | 〜姿勢をお持ちの方 | お迎えしたいと感じ |
| **general** | 〜ご経験を拝見しました | お迎えしたい方だと感じ |

#### ステップ5-3: トーン別動詞マッピング

| トーン | 候補者経験の活用動詞（bridge 末尾） | 価値観合致表現（opening 中盤） |
|---|---|---|
| **casual** | 活かせます | カルチャーとマッチしており |
| **business** | 活かしていただけます | （明示せず opening の経歴展開で示す） |
| **letter** | 活かしていただけます | （opening で「姿勢をお持ちの方を〜お迎えしたい」） |

#### ステップ5-4: ブロック別ライティング

**opening (130-180字)** — 候補者の歩みを描写 → 属性別修飾句 → 結び動詞
- 経歴動詞列挙は **2つまで**（4連はNG）
- 数字・組織語（「172床増床を控える」等）は使わない、情景表現に
- 結び末尾の読点削除（「思い、ご連絡」→「思いご連絡」）

**bridge (130-200字)** — 会社側の文脈と候補者経験の接続
- 冒頭は **会社側の文脈**から（候補者経歴の事実反復で始めない）
- 具体数字（「172床」「70床」等）はここで自然に織り込む
- 候補者の経験 → トーン別動詞（活かせます／活かしていただけます）で締め
- opening と同じ動詞（重なる・響き合う等）を使わない

**facility_intro (150-220字)** — 候補者の関心事に応える事実を3項目程度
- 候補者の属性応答（OJT・希望エリア・通勤手段等）→ 勤務条件 の順で文章のまま
- **箇条書き不採用**
- 制度列挙は3項目程度に絞る
- 「〜運用」（事務語）→「〜流れ／〜ご用意しております」

**closing_cta (60-100字)** — 短く軽い誘い
- 会社強み（オンライン説明会・ビデオオフOK・応募書類不要 等）あれば織り込む
- 「見学のみ・カジュアル面談のみでも大歓迎です」等の低ハードル
- letter トーンの場合は「具体的な復職時期が決まっていない段階でも〜」等の配慮

#### ステップ5-5: 禁止表現チェック

各候補者の生成後、以下に該当するものがあれば自動修正:

**全廃**:
- 体言止め（「〜歩み。」「〜キャリア。」）
- ダッシュ（——）多用
- 連用中止読点（「思い、ご連絡」「感じ、ご連絡」）
- 経歴動詞列挙4つ以上
- 組織語の数字を opening に
- 「運用」（事務語）

**機械的・大げさ・上から**:
- 「重なる」「かみ合う」「響き合う」「なじむ」（候補者主語の時）
- 「〜場面があるかと思います」「〜活きるのではと考えております」
- 「探していた方向と近く」「求めていた方向と近く」
- 「今まさに」「考えていた」「近いかと思います」

**下から目線**:
- 「お力をお借りしたい」「必要としています」「お力をお貸しください」

**熱烈すぎ**:
- 「ぜひ〜いただきたい」「〜こそ〜」「〜のような方を探していました」

### 6. 出力: 元CSVを更新

元のCSVファイルに以下の4列を**追加**して上書き保存する:

| 列名 | 内容 |
|------|------|
| `template_type` | `パート_初回` 等 |
| `personalized_text` | パーソナライズ文（4ブロックを連結したもの） |
| `full_scout_text` | テンプレートにパーソナライズ文・給与調整を適用した完全版 |
| `attributes_json` | 属性判定結果のJSON文字列（情報量・経験タイプ・トーン・対象区分・給与調整・警告） |

`attributes_json` の形式例:
```json
{"info":"rich","exp_type":"veteran_with_specialty","tone":"business","target":"明確","salary":"そのまま","warning":""}
```

**書き込みにはPythonのcsvモジュールを使用する**（改行・カンマのエスケープを正しく処理するため）。
元CSVがBOM付きUTF-8の場合は `utf-8-sig` で読み書きする。

```python
import csv, json

with open(path, 'r', encoding='utf-8-sig') as f:
    reader = csv.DictReader(f)
    rows = list(reader)
    fieldnames = reader.fieldnames or []

new_cols = ['template_type', 'personalized_text', 'full_scout_text', 'attributes_json']
fieldnames = list(fieldnames) + [c for c in new_cols if c not in fieldnames]

with open(path, 'w', encoding='utf-8-sig', newline='') as f:
    writer = csv.DictWriter(f, fieldnames=fieldnames)
    writer.writeheader()
    for r in rows:
        writer.writerow(r)
```

## バッチサイズの目安

pro 版は1人あたりの判定・生成・チェック量が多いため、**1回の実行で30件程度**が体感限界。
それを超える場合は、ユーザーに「[N]件あります。30件ずつ区切って進めますか？」と確認する。

## Chrome拡張インポート形式

Chrome拡張の `ImportPanel` が期待するCSV列:

```
member_id,template_type,personalized_text,full_scout_text
```

`attributes_json` は拡張側では無視されるが、CSVに残しておけば後の分析で使える。

## 既存スキルとの違い

| 項目 | csv-scout | csv-scout-pro |
|---|---|---|
| 経歴なし候補者 | 型はめマトリクス（決定的） | 4ブロック構成（揺らぎあり） |
| トーン切り替え | なし | business/casual/letter |
| 属性別 opening | なし | 5パターン |
| 給与調整 | なし | あり（モードA/B フォールバック） |
| 対象区分 | 対象/除外の2階層 | 明確/要警告/対象不明/除外の4階層 |
| 出力列 | 3列 | 4列（attributes_json 追加） |
| 推奨用途 | 大量・安定生成 | 重要案件・品質重視 |

迷ったら `csv-scout` で十分なケースは多い。pro が活きるのは:
- 病院系の business トーン案件
- 離職中・ブランク候補者の letter トーン
- 給与レンジが候補者希望と乖離していて訴求調整したい場面
- 障害福祉等、対象/対象外の境界が曖昧で警告が要る案件

## 注意事項

- profile.md に「想定年収」レンジが無い会社では、給与調整は「希望なし」扱いになる（誤訴求を避けるため）
- workspace/phase0-full-refined.md の4サンプル（S1〜S4）が「正解の温度感」の参照リファレンス
- pro でも recipes.md の NGパターン（会社固有の禁止表現）は適用する
